# Existing models run on our own data

Your supervisor's list starts at item 1, but you asked for this first: take every published
model that claims to handle Bengali or Banglish speech, run it on our test clips, and see what
it actually produces. Until now Chapter 2 compared this thesis with other systems by quoting
the error rates printed in their own papers, on their own data. That is an argument, not a
measurement, and a panel can push on it.

This closes that. Same 177 held-out clips, same references, same normaliser, same metric code
that produced the 15.8 per cent headline. One scale, so the rows can sit in one table.

Status: two of five models scored, the rest downloading. Full numbers and commands are in
RESULTS.md section 1.10; this file is the plain-language version.

## The result so far

| On our 177 held-out clips | CER | WER | What alphabet it wrote in |
|---|---|---|---|
| `whisper-small-benglish`, as it writes | 89.9% | 95.8% | Bengali script 124 clips, mixed 53, romanized 0 |
| same, after transliterating to Roman | **66.0%** | 93.3% | - |
| `BanglaASR`, as it writes | 98.6% | 100.0% | Bengali script all 177 clips |
| same, after transliterating to Roman | **73.8%** | 97.3% | - |
| off-the-shelf whisper-large-v3-turbo | 67.7% | 93.9% | Latin, but English translation |
| **yours** | **15.8%** | **42.5%** | romanized Banglish, all 177 clips |

**Neither model writes Banglish.** The one that advertises Benglish does code-switch, but it puts
the Bengali half in Bengali letters:

- reference: `hello everyone, welcome to the second class of digital logic design...`
- it wrote: `Hello এর্প্রিভান welcome to the second class of digital logic design...`

`এর্প্রিভান` is the English word *everyone* spelled in Bengali script. BanglaASR goes further and
writes even the English technical terms in Bengali letters, which is why its WER is exactly
100 per cent: it did not match a single word of any reference.

**The objection this had to survive.** A panel will say the comparison punishes these models for
their alphabet rather than their hearing. So their Bengali output was transliterated to Roman
and scored again, with two schemes tried and the better one kept per clip. That is deliberately
generous. It drops the Benglish model from 89.9 to 66.0 CER, so most of the raw gap really was
orthography. It does not close the comparison: 66.0 per cent is about where plain off-the-shelf
Whisper sits (67.7), and nowhere near 15.8. **The sentence the thesis can defend is that the gap
is not only orthography.**

## The models

Chosen to cover the three things a panel could accuse us of ducking: the one model that claims
Banglish specifically, the strongest Bengali models regardless of how they write, and both
architecture families rather than only the one we happened to use.

| # | Model | Size | Why it is in the list |
|---|---|---|---|
| 1 | `the-blue-panther/whisper-small-benglish` | 969 MB | The only public model that names Benglish and code-switching. The closest thing to a direct competitor. Its card reports WER 0.4123 but on a random 10 per cent of its own 194 clips, so the same speakers sit on both sides of the split. |
| 2 | `bangla-speech-processing/BanglaASR` | 3.9 GB | Whisper-small on Bengali Common Voice. This is the Bengali branch of our own earlier pipeline, so it is the "what we had before" row. |
| 3 | `bengaliAI/tugstugi_bengaliai-asr_whisper-medium` | 3.1 GB | Whisper-medium for Bengali. A 2026 comparison study found it gave the lowest WER of the Bengali models it tested, so it stands in for the best available. |
| 4 | `arif11/bangla-ASR-v5` | 969 MB | Whisper-small on Common Voice 13, the most downloaded Bangla ASR model on the hub. The popular default. |
| 5 | `pr0mila-gh0sh/MediBeng-Whisper-Tiny` | small | Already cited in Table 2.1 as a Bengali-English code-switched system. It translates to English rather than transcribing, and running it shows that rather than asserting it. |
| 6 | `openai/whisper-large-v3-turbo`, off the shelf | - | Already measured: CER 67.7, WER 93.9 on these exact clips. It is the base our LoRA is trained on, so it is the row the improvement is measured from. No new run needed. |

Two wav2vec2 models (`arijitx/wav2vec2-large-xlsr-bengali` and one of its siblings) are queued
behind these. They matter because wav2vec2 is the other main architecture for Bengali and a
table with only Whisper rows invites the question of whether the conclusion is an artefact of
one architecture. They run only if the downloads hold up, since they are not essential to the
argument.

## What is deliberately not in the list

- **Kaldi and GMM-HMM baselines** such as BEHE-CMDisfl. No public checkpoint to run.
- **Commercial APIs** (Google, Azure, OpenAI hosted). Running them means sending lecture audio
  to a third party, which is your call and not a decision to make quietly in a script.
- **Models with no released weights**, including the Asrarul LoRA repository mentioned in
  Chapter 2, which reports no results and ships nothing to run.

Each of these gets a line in the thesis saying why it could not be measured, rather than being
left out silently.

## How they are run

`scripts/benchmark_existing_models.py`. Two decisions in it are the ones that make the
comparison fair rather than rigged, and both should be said out loud if asked:

1. **Each model decodes under its own generation config.** Our own `evaluate.py` forces the
   `en` language and `transcribe` task tokens, which is right for our model and wrong for
   somebody else's. A Bengali model was trained to emit Bengali. Forcing it into English mode
   would break it for reasons that are our fault, and the resulting number would be
   meaningless.
2. **The script records which alphabet each model wrote in**, counting letters by Unicode
   block. This is the part that actually matters. A model that answers in Bengali script scores
   near 100 per cent error against romanized references no matter how well it heard the speech,
   and reporting that as a bare error rate would be dishonest. The script prints the script mix
   next to every error rate, and the thesis has to read them together.

Command, once the weights are down:

```
set HF_HUB_OFFLINE=1
set TRANSFORMERS_OFFLINE=1
set THESIS_FT_DIR=F:\thesisP2\ft_work_final5h
F:\thesisP2\envs\thesis_ft\Scripts\python.exe scripts\benchmark_existing_models.py ^
  --models-dir F:\thesisP2\models --limit 10
```

`--limit 10` first, to see the orthography before spending the full pass. Drop it for all 177
clips. Output lands in `F:\thesisP2\thesisP2\output\baseline_benchmark.json`.

## Reading the result before it arrives

Deciding this now, in writing, is what stops the result being reinterpreted to suit us after we
see it.

- **They write Bengali script or English.** This is what the model cards predict. Error against
  romanized references will be near 100 per cent. It turns the novelty claim in Section 2.2.2
  from an argument into a measured row, and it is the direct answer to a panel asking why this
  work was needed. The row must be reported with the script mix beside it, and the thesis must
  say plainly that the high error rate is an orthography mismatch and not evidence that these
  are bad models.
- **They write romanized Banglish and score worse than 15.8 per cent CER.** A clean comparison
  row, and the strongest version of the result.
- **They write romanized Banglish and score better than 15.8 per cent CER.** Unwelcome, and far
  better found now than by a panel. It would not touch the corpus, the board work or the notes.
  The honest response is the row in Table 2.1, a sentence in Section 5.5.1, and a changed claim
  in Chapter 2. It does not get buried.
